## v1：用户第一轮修正（2026-11-12）

用户针对上一轮 6 条评审的回应，逐条原文：

5. "评分精度不重要，极限问题看能不能收敛到满分，收敛之后精度由标准差决定。"

### 这一版解决了什么

| 原问题 | 解决情况 |
|---|---|
| 是概率命题还是确定性命题 | ✅ 明确为概率命题 |
| AI 怎么执行 | ✅ 明确为自然语言对话 |
| 目标会不会漂移 | ✅ 明确固定不变（需要补充：固定到什么程度） |
| 评分函数是什么 | ✅ 明确为不可观测的主观满意度 |
| 评分精度 | ✅ 明确为次要问题 |
| 到达还是趋近 | ✅ 明确为极限问题 |

### 这一版新引入的问题

**问题 1：「趋向于 100 这个上界」有两义，必须选一个。**

- `lim s_n = 100`：序列收敛，最终稳定在 100 附近，且任意小的邻域都会被进入；
- `sup s_n = 100`：序列的上确界是 100，但序列本身可能不收敛（例如在 96 与 100 之间来回跳，上确界 100，极限不存在）。

这两者不等价。用户真正想要的应该是前者（稳定地接近），但口述用词是"上界"，字面更像后者。**待裁定第 1 项。**

**问题 2：「对话」这个执行方式带来了记忆容量约束，而这一版完全没提。**

对话意味着 AI 的改进能力受上下文窗口限制：第 n 轮的反馈会进入上下文，但到第 n＋M 轮时可能已被挤出摘要或截断。后果有三条：

- 早期提出的约束会丢失，AI 可能在后面的轮次里把已经满足过的要求改回去（回归）；
- 用户自己也记不住早先提过的细节，无法在后续轮次复核；
- 因此净改进率会随轮次劣化，而不是保持恒定。

这一条不是吹毛求疵，它决定了命题能不能建模成马尔可夫链。忽略记忆窗口，等于假设"AI 记得所有历史"，这在对话式执行中不成立。

**问题 3：「无反馈 = 趋近满分」是判据，不是定理。**

用户不再反馈至少有四种原因，只有第一种支撑结论：

| 原因 | 真实分数 | 支撑结论？ |
|---|---|---|
| 真满意 | 接近 100 | ✅ 是 |
| 失去耐心，懒得再说 | 可能才 90 | ❌ 否 |
| 没发现问题（注意力遗漏、专业盲区） | 未知 | ❌ 否 |
| 以为已经完成，实际没验收 | 未知 | ❌ 否 |

所以要写进假设：**用户的停止只由满意度驱动，不受耐心、时间、注意力影响**。这是强假设，现实中通常不成立。**待裁定第 2 项。**

**问题 4：停止点是阈值，不是零。这一条是全篇最关键的结构性问题。**

用户判断是否再提意见，用的是「这个差距大到值得我再说一次吗」，不是「这个差距大于零吗」。设用户愿意再折腾一轮的最小差距为阈值 θ，则停止条件近似是 `d_n < θ`（d 为剩余差距），而不是 `d_n = 0`。

于是停止那一刻的差距落在 `[0, θ)` 区间内，也就是说：

```
停止时 s_τ ∈ (100 - θ, 100]
```

θ 大于零时，**"收敛到 100"在数学上不成立**，能证明的最强结论是"收敛到 100 减掉 θ 以上的某个值"。而 θ 由人的注意力成本决定，不是 AI 能优化的参数。

这一条改写了整个命题：真正可证、也可实测的，不是"能否到 100"，而是"**停下来的时候离 100 还有多远，这段距离由什么决定**"。**待裁定第 3 项。**

**问题 5：「反馈是评分本身但不是具体数值」把分数变成了不可观测变量，命题性质变了。**

这一条修正本身是对的（现实中用户确实不会给数字），但后果要说清楚：一旦分数不可观测，命题就从「实数列的收敛性」变成了「隐状态加观测信号的状态估计问题」：

- 隐变量 `s_n`：真实满意度，看不到；
- 可观测 `f_n ∈ {0, 1}`：这一轮有没有给反馈。

从二值信号序列 `f_1, f_2, …` 只能推断「用户在哪一轮停了」，推不出分数的轨迹。所以命题不能再以「分数序列」为主体，必须以「反馈内容 + 停止时刻」为主体。数学工具也从实分析（单调有界定理）换成随机过程与信息论（隐马尔可夫、信道容量）。

另外要区分两条通道，混淆会致命：

| 通道 | 载体 | 作用 | 可观测 |
|---|---|---|---|
| 终止通道 | `f_n`（有无反馈） | 决定什么时候停 | ✅ 可观测 |
| 改进通道 | `c_n`（反馈说了什么） | 决定往哪个方向改、能传多少信息 | 半观测（内容可读，含义有噪声） |

只观测 `f_n`，得不到任何改进方向。"反馈是评分本身"，但**评分不等于信息**：它只说明"未达标"，不说明"差在哪"。

**问题 6：「收敛之后精度由标准差决定」方向要修正。**

噪声不是决定"精度"，而是决定"停止点偏低多少"。推导如下：

设用户判断带噪声 `s̃_n = s_n + ε_n`，停止条件是 `s̃_n ≥ 100 - θ`。代入得 `s_n ≥ 100 - θ - ε_n`。当 `ε_n > 0`（那一次判断偏宽松），用户会在真实差距**仍大于 θ** 时停止。

而 `ε_n < 0`（判断偏严格）时用户继续反馈，于是真实质量继续提高，直到下一次判断不再偏严格为止。

结论是单向的：**噪声只会让停止更早，不会让停止更晚**。σ 越大，最终质量系统性越低，偏低量大致在 σ 的量级（正态噪声下，触发停止那一次的条件期望约为 0.5σ 到 0.8σ）。准确表述是「噪声让停止点向下偏移」，不是「噪声决定精度」。**待裁定第 4 项。**

## v2：严谨化提案（2026-11-12，助手起草）

### 符号表

| 符号 | 含义 | 可观测 |
|---|---|---|
| `P_n` | 第 n 轮的项目状态 | ✅ |
| `s_n = S(P_n)` | 真实满意度分数，0 到 100 | ❌ |
| `d_n = 100 - s_n` | 剩余差距 | ❌ |
| `c_n` | 第 n 轮用户反馈的自然语言内容（改进通道） | 半观测 |
| `f_n` | 第 n 轮是否有反馈，二值（终止通道） | ✅ |
| `τ` | 停止时刻，第一个 `f_n = 0` 的 n | ✅ |
| `θ` | 用户愿意再提一次意见的最小差距阈值 | ❌（可间接实测） |
| `ε_n, σ` | 用户满意度判断的噪声与其标准差 | ❌（可间接实测） |
| `b` | 每轮反馈携带的有效信息量（比特） | ❌（可间接实测） |
| `M` | AI 对话上下文的记忆窗口（轮） | 半观测 |
| `H` | 满分项目所需的设计信息总量（比特） | ❌ |

### 假设清单

| 编号 | 假设 | 性质 |
|---|---|---|
| H1 | 目标函数 S 在迭代期间保持不变 | 【用户裁定】v1 第 2 条 |
| H2 | 停止只由满意度驱动，不受耐心、时间、注意力影响 | 【待裁定】 |
| H3 | 每轮反馈内容能指出至少一个现存缺陷（改进通道有效） | 【待裁定】 |
| H4 | 单轮期望净改进为正（修掉的缺陷数大于引入的缺陷数） | 【待裁定】 |
| H5 | AI 的有效记忆窗口为 M 轮，超出窗口的历史不参与决策 | 【待裁定】 |

### 主命题（可证版本）

> 在上表五条假设成立的条件下：
>
> **(i)** 满意度序列 `s_n` 几乎必然收敛到某个极限 `s_∞ ≤ 100`。
>
> **(ii)** 停止时的差距满足 `d_τ < θ`，即 `s_τ ≥ 100 - θ`，仅当判断无噪声（σ = 0）时严格成立。
>
> **(iii)** 判断有噪声时，`E[s_τ] < 100 - θ`，偏低量与 σ 同阶（正态噪声下约 0.5σ 到 0.8σ）。
>
> **(iv)** 若有效信息容量 `M·b < H`（记忆窗口乘每轮信息量，小于满分所需信息总量），则 `s_∞ ≤ 100 - δ`，δ 由缺失信息的价值决定，无论迭代多少次都不会再提高。
>
> **(v)** 原命题「足够多次反馈后趋近 100」成立，当且仅当 `θ = 0`、`σ = 0`、`M·b ≥ H` 三条同时成立。

### 对 (v) 的说明

三条条件里，`θ = 0`（用户不设反馈阈值）与 `σ = 0`（用户判断完全稳定）都违背人的实际行为，`M·b ≥ H` 要求反馈通道的总信息量覆盖满分项目的全部设计信息。三条同时成立的情况实践中几乎不存在。

所以原命题的严格版本为假，但这不是坏消息：**能证的是"停止点与 100 的差距由 θ、σ、M·b 三个参数决定"，这比"能不能到 100"有用得多，因为三个参数都可实测、可优化**：

| 参数 | 怎么改善 | 代价 |
|---|---|---|
| θ（反馈阈值） | 用户提高要求、把验收标准写下来 | 用户时间成本上升 |
| σ（判断噪声） | 用清单化验收代替临场感觉、多人交叉评审 | 流程变重 |
| M·b（信息容量） | 分阶段固定约束、把已完成项写进文档而非留在对话里 | AI 侧工程改造 |

### 一个可算的例子

假设：初始 80 分（20 个未通过检查项）、用户反馈阈值 θ = 2 分、判断噪声 σ = 1 分、每轮修好概率 p = 0.6、弄坏概率 q = 0.4（净改进 0.2 项/轮）。

- 期望轮数 `≈ 20 / 0.2 = 100` 轮（此为不考虑 θ 的上界；θ 会在差距小于 2 分时提前终止，实际远少于 100 轮）；
- 停止时差距 `< 2`，叠加噪声，期望停止点在 100 − 2 − 0.5×1 ≈ **97.5 分**；
- 结论：即使迭代一百轮，最终稳定在 97 到 98 分附近，不会到 100。

如果把 θ 降到 0.5 分、σ 降到 0.3 分，同样条件下期望停止点在 **99.3 分**附近。

**这组数字说明：最终质量由人的反馈行为决定，不由 AI 的迭代次数决定。** 想提高，改的不是"多反馈几次"，而是"降低反馈阈值、降低判断噪声"。

## v3：三判据框架（2026-11-12，用户定义目标 + 助手形式化）

### 用户第三轮原话（逐字）

> 那我明白我想要的是什么了：
> 1. 首先我想要证明能不能收敛到某个值(不需要是100);
> 2. 如果能收敛到某个值，这个值是大于100还是小于100，如果小于100且用户还是不满意(涉及精度问题，小于100且小太多了，超出了用户能够忍受的精度)则这个项目的分数上限没办法让用户满意；如果在100附近(小于100的时候在用户可忍受的精度内)或者大于100，则这个项目可以到达让用户满意的程度。
> 3. 需要用户反馈多少轮，用户需要投入时间精力，需要的轮数太多可能超出用户可忍受的范围。

### 这一版的核心变化：从一个命题变成三条判据

用户自己把“能不能做到满意”拆成了三件事，而这三件事在数学上是分离的，可以分别证明、分别失败：

| 用户表述 | 数学名称 | 判据编号 |
|---|---|---|
| ① 能不能收敛到某个值 | 收敛性 | **J1** |
| ② 收敛值离 100 多远、能否接受 | 收敛值充分性 | **J2** |
| ③ 需要多少轮、能否坚持 | 收敛速率 | **J3** |

三条必须同时成立，才叫“能靠反馈做到用户满意”。三条里任何一条失败，失败模式与处理方式都不同（见“J 失败诊断表”）。

### v2 有一条假设被这一版推翻

**H2（停止只由满意度驱动）不再成立**。用户第 2 条承认了“用户停止反馈但不满意”这种情况存在（θ > δ 的情形），第 3 条又承认“轮数太多会超出可忍受范围”。所以终止必须拆成两种：

| 终止类型 | 触发条件 | 结果 | 是否成功 |
|---|---|---|---|
| **内部终止** | 剩余差距小于 θ（用户觉得不值得再说） | 停在 `d_τ ∈ [λθ, θ)` | 看 θ 与 δ 的关系，可能成功可能失败 |
| **外部终止** | 反馈轮数超过 N_max（耐心耗尽） | 停在 `s_{N_max}` | 必然失败（`s < 100 − δ`） |

这一拆解解释了实践中最常见的结局：项目不是“做到满意而结束”，而是“用户放弃而结束”。

### v3 新增符号

| 符号 | 含义 | 与 v2 符号的关系 |
|---|---|---|
| `δ` | **满意阈值**：最终差距小于它才叫满意 | 与 θ 不同，见下 |
| `N_max` | **耐心预算**：用户最多愿意反馈的轮数 | 新引入 |
| `λ` | 等比收敛率：每轮**保留**的剩余差距比例（0 < λ < 1） | v2 用“修掉固定比例 c”，本版改用 λ 便于写递推 |

递推关系：`d_{n+1} = λ·d_n`，其中 `d_n = 100 − s_n` 是剩余差距，解为 `d_n = d_0·λ^n`。

### 第一条修正：不存在“大于 100”

量表封顶 100，所以 `s_n ≤ 100` 对每一轮成立，极限也只能 `≤ 100`。用户原话里的“大于 100”这个分支不存在。只剩两种：`s_∞ = 100`（需零阈值零噪声，现实中基本不发生）或 `s_∞ = 100 − d`。所以判据统一写成 **`d ≤ δ`**。

### 第二条修正：θ 与 δ 是两个不同的阈值

| 符号 | 含义 | 作用 | 可否观测 |
|---|---|---|---|
| **θ** | 差距多大时才值得再提一次意见 | 决定**什么时候停止反馈**（行为阈值） | 可间接测 |
| **δ** | 最终差距多小才算满意 | 决定**停下之后算不算成功**（评价阈值） | 需独立定义 |

两者关系决定三种结局：

| 关系 | 结局 |
|---|---|
| θ ≤ δ | 停止即满意（差距 < θ ≤ δ），系统自洽 |
| λθ < δ < θ | 停止点可能落在满意区，也可能落在不满意区（看当轮跳幅） |
| λθ ≥ δ | **必然不满意**：停止点下界已越过满意线 |

这张表是 v3 最有用的结论之一：**“用户不再反馈”和“用户满意”不是一回事，两者的差距由一个代数条件决定。**

### J1：收敛性

```
J1：lim s_n 存在（等价于 liminf s_n = limsup s_n）
```

用户已裁定采用 `lim`（收敛），不采用 `sup`（上确界），因为 sup 允许“某一次侥幸满分、之后掉回去”，那不是“趋近”。

- **充分条件**：单轮期望净改进为正（修掉的缺陷数 > 引入的缺陷数），缺陷数有限，则有限状态马尔可夫链、净漂移为负，以概率 1 收敛到吸收集。
- **失败表现**：`liminf < limsup`，即在两个水平之间反复跳（修 A 破坏 B、在两种实现间来回切换）。
- **注意**：收敛不要求单调（可以振荡着收敛，只要振幅趋近于零），也不要求“到达”极限值。

### J2：收敛值充分性（两个形式）

**粗略形式（期望位置）**：

```
s_∞ ≈ 100 − max(θ, 0.8σ) − Δ
J2：max(θ, 0.8σ) + Δ ≤ δ
```

- `θ`：反馈阈值；
- `0.8σ`：判断噪声让停止点向下偏移的量（正态噪声下 `E[ε | ε>0] = σ√(2/π) ≈ 0.798σ`）；
- `Δ`：信息缺口（反馈通道没说全的部分）。

**关键含义**：`max` 说明两边取其大者。若 θ = 2 分、σ = 0.5 分，天花板是 98 分；若 θ = 0.3 分、σ = 1 分，**降 θ 完全没有收益**，天花板仍是 99.2 分（被 σ 卡住）。所以优化纪律是：**θ 的有效下限是 0.8σ，θ 降到这个值以下就白降。**想靠“用户要求更严格”提分，必须同时把判断噪声压下去。

**精确形式（停止点位置）**：等比收敛下，内部终止一定发生在上一轮还 ≥ θ、这一轮首次 < θ 的时刻，所以

```
d_τ ∈ [λθ, θ)
```

于是上面那张三分法表可以写成硬条件：

```
保证满意：θ ≤ δ
可能满意：λθ < δ < θ
必然不满意：λθ ≥ δ
```

**数字例子**：δ = 1（差 1 分以内算满意）、θ = 2（差 2 分以上才值得再提）、λ = 0.7（每轮只修掉 30% 剩余差距）。则 `λθ = 1.4 > δ = 1`，**每次内部终止都落在 99 分以下，必然不满意**。要改变这个结局只有两条路：① 把 θ 降到 1 分以内（要求更严）；② 把 λ 降到 0.5 以下（每轮修掉一半以上剩余差距）。这条代数条件说明，为什么很多项目“改到用户不再说话”时，离用户真正想要的还差一截。

### J3：收敛速率

```
τ ≈ ln(d_0 / d_τ) / ln(1/λ)
J3：τ ≤ N_max
```

`d_0 = 100 − s_0` 是起点差距，`d_τ` 是停止时的差距。代数字（λ = 0.7，ln(1/0.7) ≈ 0.357）：

| 目标 | d_0 / d_τ | 需要轮数 |
|---|---|---|
| 80 → 98 | 20 / 2 = 10 | ln10 / 0.357 ≈ **7 轮** |
| 80 → 99 | 20 / 1 = 20 | ln20 / 0.357 ≈ **9 轮** |
| 80 → 99.9 | 20 / 0.1 = 200 | ln200 / 0.357 ≈ **15 轮** |
| 99 → 99.9 | 1 / 0.1 = 10 | ln10 / 0.357 ≈ **7 轮** |

两条结论：

1. **轮数对精度是对数增长**。从 98 提到 99.9 只多 8 轮，成本可控；
2. **“最后一公里”的难度等于“前面一整段”的难度**。99 → 99.9（比值 10）与 80 → 98（比值 10）花一样多的轮数。所以不会因为“快到了”而变快，每一分的边际成本在上升。

若改用线性模型（每轮固定涨 Δ 分），则 `τ = (d_0 − d_τ)/Δ`，数字更悲观：80 → 99.9 需要 199 轮。现实中 AI 的改进更接近等比（先修大问题、再修细节），故以等比模型为主。

### J 失败诊断表

| 判据 | 失败的数学表现 | 体感 | 该改什么 |
|---|---|---|---|
| J1 | `liminf < limsup`（两点间反复跳） | 越改越乱，同一处反复改 | 提高单轮净改进率、加回归检查、降低破坏率 |
| J2 | `max(θ, 0.8σ) + Δ > δ` 或 `λθ ≥ δ` | 稳定了，但就是差一口气 | 写清单降 σ、降 θ、把约束写进文档补 Δ |
| J3 | `τ > N_max` | 改到一半我放弃了 | 提高每轮信息量、减少无效轮次、缩小 δ |

### 一条必须点明的联动：J1 失败会连带 J3 外部终止

若不收敛（J1 失败），用户永远不会进入内部终止，因为每一轮都能挑出新毛病，差距不降。于是轮数不是趋近有限值，而是一直消耗到耐心耗尽，触发**外部终止**，停在 `s_{N_max} < 100 − δ`，也就是失败。

所以 J3 不只是效率指标，它还是 J1 的兜底探针：**一旦发现轮数在失控增长，通常意味着 J1 已经出问题了。**
