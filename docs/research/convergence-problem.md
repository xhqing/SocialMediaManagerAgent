## v0：原始口述（2026-11-12）

> 我想从数学上证明一个问题：假设让 AI 做一个项目，给项目打分，最高分是 100 分，最低分是 0 分，假设 AI 第一次完成这个项目能拿到 80 分，然后需要用户的反馈，用户反馈之后 AI 继续修改完善这个项目，能否证明在足够多次反馈完善之后这个项目能够拿到 100 分？

**这一版的问题**（第一轮评审，共 6 处，详见「第一轮评审」节）：AI 未定义、项目同一性未定义、评分函数是否固定未定义、评分精度未交代、反馈通道性质未交代、"足够多次之后拿到 100 分"混了三组不同的数学概念。

5. "评分精度不重要，极限问题看能不能收敛到满分，收敛之后精度由标准差决定。"

### 这一版解决了什么

| 原问题 | 解决情况 |
|---|---|
| 是概率命题还是确定性命题 | ✅ 明确为概率命题 |
| AI 怎么执行 | ✅ 明确为自然语言对话 |
| 目标会不会漂移 | ✅ 明确固定不变（需要补充：固定到什么程度） |
| 评分函数是什么 | ✅ 明确为不可观测的主观满意度 |
| 评分精度 | ✅ 明确为次要问题 |
| 到达还是趋近 | ✅ 明确为极限问题 |

### 这一版新引入的问题

**问题 1：「趋向于 100 这个上界」有两义，必须选一个。**

- `lim s_n = 100`：序列收敛，最终稳定在 100 附近，且任意小的邻域都会被进入；
- `sup s_n = 100`：序列的上确界是 100，但序列本身可能不收敛（例如在 96 与 100 之间来回跳，上确界 100，极限不存在）。

这两者不等价。用户真正想要的应该是前者（稳定地接近），但口述用词是"上界"，字面更像后者。**待裁定第 1 项。**

**问题 2：「对话」这个执行方式带来了记忆容量约束，而这一版完全没提。**

对话意味着 AI 的改进能力受上下文窗口限制：第 n 轮的反馈会进入上下文，但到第 n＋M 轮时可能已被挤出摘要或截断。后果有三条：

- 早期提出的约束会丢失，AI 可能在后面的轮次里把已经满足过的要求改回去（回归）；
- 用户自己也记不住早先提过的细节，无法在后续轮次复核；
- 因此净改进率会随轮次劣化，而不是保持恒定。

这一条不是吹毛求疵，它决定了命题能不能建模成马尔可夫链。忽略记忆窗口，等于假设"AI 记得所有历史"，这在对话式执行中不成立。

**问题 3：「无反馈 = 趋近满分」是判据，不是定理。**

用户不再反馈至少有四种原因，只有第一种支撑结论：

| 原因 | 真实分数 | 支撑结论？ |
|---|---|---|
| 真满意 | 接近 100 | ✅ 是 |
| 失去耐心，懒得再说 | 可能才 90 | ❌ 否 |
| 没发现问题（注意力遗漏、专业盲区） | 未知 | ❌ 否 |
| 以为已经完成，实际没验收 | 未知 | ❌ 否 |

所以要写进假设：**用户的停止只由满意度驱动，不受耐心、时间、注意力影响**。这是强假设，现实中通常不成立。**待裁定第 2 项。**

**问题 4：停止点是阈值，不是零。这一条是全篇最关键的结构性问题。**

用户判断是否再提意见，用的是「这个差距大到值得我再说一次吗」，不是「这个差距大于零吗」。设用户愿意再折腾一轮的最小差距为阈值 θ，则停止条件近似是 `d_n < θ`（d 为剩余差距），而不是 `d_n = 0`。

于是停止那一刻的差距落在 `[0, θ)` 区间内，也就是说：

```
停止时 s_τ ∈ (100 - θ, 100]
```

θ 大于零时，**"收敛到 100"在数学上不成立**，能证明的最强结论是"收敛到 100 减掉 θ 以上的某个值"。而 θ 由人的注意力成本决定，不是 AI 能优化的参数。

这一条改写了整个命题：真正可证、也可实测的，不是"能否到 100"，而是"**停下来的时候离 100 还有多远，这段距离由什么决定**"。**待裁定第 3 项。**

**问题 5：「反馈是评分本身但不是具体数值」把分数变成了不可观测变量，命题性质变了。**

这一条修正本身是对的（现实中用户确实不会给数字），但后果要说清楚：一旦分数不可观测，命题就从「实数列的收敛性」变成了「隐状态加观测信号的状态估计问题」：

- 隐变量 `s_n`：真实满意度，看不到；
- 可观测 `f_n ∈ {0, 1}`：这一轮有没有给反馈。

从二值信号序列 `f_1, f_2, …` 只能推断「用户在哪一轮停了」，推不出分数的轨迹。所以命题不能再以「分数序列」为主体，必须以「反馈内容 + 停止时刻」为主体。数学工具也从实分析（单调有界定理）换成随机过程与信息论（隐马尔可夫、信道容量）。

另外要区分两条通道，混淆会致命：

| 通道 | 载体 | 作用 | 可观测 |
|---|---|---|---|
| 终止通道 | `f_n`（有无反馈） | 决定什么时候停 | ✅ 可观测 |
| 改进通道 | `c_n`（反馈说了什么） | 决定往哪个方向改、能传多少信息 | 半观测（内容可读，含义有噪声） |

只观测 `f_n`，得不到任何改进方向。"反馈是评分本身"，但**评分不等于信息**：它只说明"未达标"，不说明"差在哪"。

**问题 6：「收敛之后精度由标准差决定」方向要修正。**

噪声不是决定"精度"，而是决定"停止点偏低多少"。推导如下：

设用户判断带噪声 `s̃_n = s_n + ε_n`，停止条件是 `s̃_n ≥ 100 - θ`。代入得 `s_n ≥ 100 - θ - ε_n`。当 `ε_n > 0`（那一次判断偏宽松），用户会在真实差距**仍大于 θ** 时停止。

而 `ε_n < 0`（判断偏严格）时用户继续反馈，于是真实质量继续提高，直到下一次判断不再偏严格为止。

结论是单向的：**噪声只会让停止更早，不会让停止更晚**。σ 越大，最终质量系统性越低，偏低量大致在 σ 的量级（正态噪声下，触发停止那一次的条件期望约为 0.5σ 到 0.8σ）。准确表述是「噪声让停止点向下偏移」，不是「噪声决定精度」。**待裁定第 4 项。**

## v2：严谨化提案（2026-11-12，助手起草）

### 符号表

| 符号 | 含义 | 可观测 |
|---|---|---|
| `P_n` | 第 n 轮的项目状态 | ✅ |
| `s_n = S(P_n)` | 真实满意度分数，0 到 100 | ❌ |
| `d_n = 100 - s_n` | 剩余差距 | ❌ |
| `c_n` | 第 n 轮用户反馈的自然语言内容（改进通道） | 半观测 |
| `f_n` | 第 n 轮是否有反馈，二值（终止通道） | ✅ |
| `τ` | 停止时刻，第一个 `f_n = 0` 的 n | ✅ |
| `θ` | 用户愿意再提一次意见的最小差距阈值 | ❌（可间接实测） |
| `ε_n, σ` | 用户满意度判断的噪声与其标准差 | ❌（可间接实测） |
| `b` | 每轮反馈携带的有效信息量（比特） | ❌（可间接实测） |
| `M` | AI 对话上下文的记忆窗口（轮） | 半观测 |
| `H` | 满分项目所需的设计信息总量（比特） | ❌ |

### 假设清单

| 编号 | 假设 | 性质 |
|---|---|---|
| H1 | 目标函数 S 在迭代期间保持不变 | 【用户裁定】v1 第 2 条 |
| H2 | 停止只由满意度驱动，不受耐心、时间、注意力影响 | 【待裁定】 |
| H3 | 每轮反馈内容能指出至少一个现存缺陷（改进通道有效） | 【待裁定】 |
| H4 | 单轮期望净改进为正（修掉的缺陷数大于引入的缺陷数） | 【待裁定】 |
| H5 | AI 的有效记忆窗口为 M 轮，超出窗口的历史不参与决策 | 【待裁定】 |

### 主命题（可证版本）

> 在上表五条假设成立的条件下：
>
> **(i)** 满意度序列 `s_n` 几乎必然收敛到某个极限 `s_∞ ≤ 100`。
>
> **(ii)** 停止时的差距满足 `d_τ < θ`，即 `s_τ ≥ 100 - θ`，仅当判断无噪声（σ = 0）时严格成立。
>
> **(iii)** 判断有噪声时，`E[s_τ] < 100 - θ`，偏低量与 σ 同阶（正态噪声下约 0.5σ 到 0.8σ）。
>
> **(iv)** 若有效信息容量 `M·b < H`（记忆窗口乘每轮信息量，小于满分所需信息总量），则 `s_∞ ≤ 100 - δ`，δ 由缺失信息的价值决定，无论迭代多少次都不会再提高。
>
> **(v)** 原命题「足够多次反馈后趋近 100」成立，当且仅当 `θ = 0`、`σ = 0`、`M·b ≥ H` 三条同时成立。

### 对 (v) 的说明

三条条件里，`θ = 0`（用户不设反馈阈值）与 `σ = 0`（用户判断完全稳定）都违背人的实际行为，`M·b ≥ H` 要求反馈通道的总信息量覆盖满分项目的全部设计信息。三条同时成立的情况实践中几乎不存在。

所以原命题的严格版本为假，但这不是坏消息：**能证的是"停止点与 100 的差距由 θ、σ、M·b 三个参数决定"，这比"能不能到 100"有用得多，因为三个参数都可实测、可优化**：

| 参数 | 怎么改善 | 代价 |
|---|---|---|
| θ（反馈阈值） | 用户提高要求、把验收标准写下来 | 用户时间成本上升 |
| σ（判断噪声） | 用清单化验收代替临场感觉、多人交叉评审 | 流程变重 |
| M·b（信息容量） | 分阶段固定约束、把已完成项写进文档而非留在对话里 | AI 侧工程改造 |

### 一个可算的例子

假设：初始 80 分（20 个未通过检查项）、用户反馈阈值 θ = 2 分、判断噪声 σ = 1 分、每轮修好概率 p = 0.6、弄坏概率 q = 0.4（净改进 0.2 项/轮）。

- 期望轮数 `≈ 20 / 0.2 = 100` 轮（此为不考虑 θ 的上界；θ 会在差距小于 2 分时提前终止，实际远少于 100 轮）；
- 停止时差距 `< 2`，叠加噪声，期望停止点在 100 − 2 − 0.5×1 ≈ **97.5 分**；
- 结论：即使迭代一百轮，最终稳定在 97 到 98 分附近，不会到 100。

如果把 θ 降到 0.5 分、σ 降到 0.3 分，同样条件下期望停止点在 **99.3 分**附近。

**这组数字说明：最终质量由人的反馈行为决定，不由 AI 的迭代次数决定。** 想提高，改的不是"多反馈几次"，而是"降低反馈阈值、降低判断噪声"。

## 待用户裁定的 5 项

1. **主命题用收敛还是上确界**：推荐 `lim s_n = 100` 的趋近版本（稳定接近），不采用"上确界为 100"（允许来回震荡）。
2. **是否接受 H2（停止只由满意度驱动）**：接受则命题可证，但命题变成理想化模型；不接受则要引入耐心衰减函数，模型复杂度上升。
3. **是否接受 θ > 0 作为模型的核心参数**：这一条决定了结论是"能到 100"还是"只能到 100 减一点"。我认为必须接受，因为它是现实机制。
4. **是否接受"噪声让停止点单向偏低"这个方向性结论**（v1 第 5 条的修正）。
5. **是否把记忆窗口 M 纳入模型**：不纳入等于假设 AI 记得全部历史。
