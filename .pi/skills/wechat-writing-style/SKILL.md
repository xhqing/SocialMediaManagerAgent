# 微信公众号写作风格指南

> **来源与改动**：原版是 yaoleifly/wechat-writing-style（MIT）。本版做了三处改动：删掉原作者的内容领域清单（海外开户、跨境支付、自托管等，与本项目无关）；删掉与 qu-ai-wei 冲突的一条（原版允许「说白了」「说穿了」这类起手式，qu-ai-wei 第 9 条明确要求删，以 qu-ai-wei 为准）；合规部分改为指向项目 `AGENTS.md` 的「合规红线与发布前检查」，避免两处规则各说各话。其余风格要求保留原样。

## 风格四条

### 一、开门见山（2026-11-12 用户立规，强化原来的“结论先行”）

读者点进来说明他对题目感兴趣。所以正文第一段就该是扣题的内容，不做任何与题目无关的铺垫。

开头直接给判断，不做铺垫。读者看前三句话就该知道这篇要讲什么。

**禁止写进正文的内容**（都属于“无关废话”）：

| 类型 | 例子 |
|---|---|
| 元信息 | “本文是什么：一篇关于……的科普文” |
| 写作大纲 | 文章结构规划、每节要讲什么、“自己的逻辑大纲” |
| 元叙述 | “这篇文章只回答了三个问题里的第一个” |
| 交付物 | 备选标题、推荐理由、修改记录、写作备注 |
| 背景铺垫 | “随着人工智能的快速发展”“在当今时代” |

**判断标准一句话**：这段话删掉，读者会不会少学到东西？不会，就删。

合格的写法是先把结论摆出来，再解释为什么。不合格的写法是先讲背景、讲趋势、讲“随着……的发展”，读到第五段还没见到观点。

### 二、句子短，但每段有实质信息

第一人称，像跟人说话。长句拆开，一句话说一件事。

口语不等于灌水。口语化是表达方式，不是降低信息密度。每段都要有读者拿走就能用的东西：一个具体做法、一组数字、一个判断。

**起手式按 qu-ai-wei 的要求来**：不用「说白了」「说穿了」「先说结论」这类话开头，直接给判断。原版 skill 允许这些词，两处规则冲突时以 qu-ai-wei 为准。

### 三、段落短，留白多

每段一到三句。需要强调或转折时，一句话单独成段。

段与段之间留呼吸感。手机屏幕上，一段超过五行就开始压人。

### 四、举例要具体

用真实的工具名、真实的场景、真实的数据。避免「显著提升」「大幅优化」这类空话。

有亲身经历就用亲身经历，那是别人抄不走的部分。

## 格式规范

- 中英文之间加空格，中文与数字之间加空格
- **全文不用破折号**，用逗号、句号或分成两句
- 输出 Markdown
- emoji 克制，全文最多一个，放语境自然的位置
- 主标题要有点击欲望，同时把核心关键词放进去（公众号站内有搜索）
- 小标题用口语化的短语或问句，不用学术体、不用新闻体
- 一篇写完给 5 到 10 个备选标题，标出推荐项和理由，**在对话里给，不写进文章文件**
- **交付与正文分开（2026-11-12 用户立）**：文章文件里只放读者要读的内容（标题、正文、小标题）。备选标题、推荐理由、修改说明、写作备注、“本文是什么”类的元信息块、写作大纲，一律只在对话里给。理由：文章会被直接发表或同步到博客，写进文件的部分就会原样发出去。
- **收稿前自检（开终前跑一遍）**：
  ```bash
  grep -nE "本文是什么|备选标题|推荐第|这篇文章只回答|写作大纲" <文章文件>
  grep -nE "先把.{1,12}说清楚|这是.{1,20}不是|不是.{1,25}是|而是" <文章文件>
  ```
  第一条查无关废话，第二条查 AI 腔对偶句（规则与例外见项目 `AGENTS.md` 的“中文表达纪律”节）。有命中就人工判断。

## 写作流程

1. **起稿**：按用户给的要点或大纲写初稿，走上面四条风格
2. **敏感性审查**：过一遍项目 `AGENTS.md` 的「合规红线与发布前检查清单」（导流、AI 标注、金融内容），以及平台敏感词
3. **事实核查**：工具、政策、数据逐个确认，不确定的标出来，不拿猜的答案顶上
4. **可读性**：逐段问一句「读到这里的理由是什么」，答不上来的段落删掉或改
5. **标题**：给 5 到 10 个备选，标推荐项（在对话里给，不进文章文件）
6. **交付**：Markdown，公式与图片按 `wechat-mp` 的规则处理

## 素材太少时怎么办

用户只给几个关键词时，可以扩写成完整文章，但不许编事实。缺的地方标出来问，或者留空位。

用户要求精简时，先删过渡句和修饰语，保住核心信息和具体案例。

## 好段落与坏段落

合格的写法：

> 我用的是 Claude Opus 4.6，开了 extended thinking。具体怎么用？不是让它替我「写文章」，是让它帮我「扩充和润色」。先自己写 500 字粗稿，再让 Claude 补论据、优化表达、查逻辑漏洞。

不合格的写法：

> 在人工智能辅助写作领域，笔者采用了 Anthropic 公司推出的 Claude Opus 4.6 大语言模型，结合其深度思考功能模块，对初稿进行了系统性的内容扩展与文本优化。

差别不在长短，在于后一段把「我做了什么」换成了「一套流程被执行了」。动词被名词吃掉，人就消失了。
